# Contributing

Thank you for helping improve this Community Edition.

## Good contributions

- clarify architecture patterns;
- add safe lab scenarios;
- improve diagrams and documentation;
- add framework-independent governance examples;
- add tests or examples that do not require production credentials;
- report security or isolation weaknesses in the sample design.

## Boundaries

Please do **not** submit:

- real customer data, source code, secrets, tokens, passwords, API keys, or private keys;
- proprietary prompts, internal company documents, or production configurations;
- examples that weaken approval, project/workspace isolation, or least-privilege controls;
- destructive automation enabled by default.

## Pull requests

1. Open an issue first for a material architecture change.
2. Keep changes small and traceable.
3. Explain the problem, proposed pattern, risk impact, and validation evidence.
4. Update relevant architecture/change-log documentation.
5. Confirm no confidential data or secret is included.
